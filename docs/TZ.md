# TZ — Техническое задание TransApp v1

---

## 1. Функциональные требования

### 1.1 Telegram Bot

| ID | Требование |
|---|---|
| F-B-01 | Команда `/start` — регистрация пользователя, приветствие, кнопка открытия Mini App |
| F-B-02 | Команда `/tr` (reply) — перевод цитируемого сообщения на язык пользователя по умолчанию |
| F-B-03 | Команда `/tr [code]` (reply) — перевод на указанный язык (`/tr en`, `/tr de`) |
| F-B-04 | Команда `/to [code] [text]` — перевод произвольного текста и возврат результата |
| F-B-05 | Inline-режим: `@transappbot [text]` — возвращает варианты перевода на top-3 языков пользователя |
| F-B-06 | Команда `/lang [code]` — смена языка по умолчанию |
| F-B-07 | Команда `/quota` — показ остатка символов и тарифа |
| F-B-08 | Команда `/help` — справка по командам |
| F-B-09 | Callback-кнопки: апгрейд, настройки, открыть Mini App |
| F-B-10 | При превышении лимита — сообщение с CTA к апгрейду |
| F-B-11 | Поддержка команды `/group_translate on|off` для групп (требует admin-прав у пользователя) |

### 1.2 Mini App (WebApp)

| ID | Требование |
|---|---|
| F-M-01 | Открывается через `/start` или кнопку в боте |
| F-M-02 | Авторизация через `initData` (Telegram WebApp SDK) — без паролей |
| F-M-03 | Дашборд: остаток символов, тариф, дата сброса, график за 30 дней |
| F-M-04 | Настройки языка: язык по умолчанию, список любимых языков (drag-and-drop) |
| F-M-05 | Управление авто-переводами: добавить/удалить чат, включить/выключить, задать направление |
| F-M-06 | Просмотр переводов выбранного чата: двухколоночно оригинал + перевод |
| F-M-07 | Страница биллинга: текущий план (мес/год), выбор периода оплаты, история платежей, кнопка апгрейда |
| F-M-08 | Реферальная ссылка и статистика приглашённых |
| F-M-09 | Поддержка тёмной/светлой темы (Telegram theme variables) |
| F-M-10 | Локализация интерфейса: RU, EN (добавляются по запросу) |

### 1.3 Backend API

| ID | Требование |
|---|---|
| F-A-01 | Авторизация через Telegram initData (HMAC-валидация) |
| F-A-02 | CRUD пользователей: создание при первом `/start`, хранение настроек |
| F-A-03 | Endpoint перевода: принимает текст + пара языков, возвращает перевод |
| F-A-04 | Кэширование переводов: одинаковый текст + пара языков → из кэша (Redis) |
| F-A-05 | Подсчёт символов: каждый перевод списывает символы с баланса пользователя |
| F-A-06 | Rate limiting: не более 10 запросов/сек на пользователя |
| F-A-07 | Webhook-эндпоинт для Telegram Bot API |
| F-A-08 | Управление авто-переводами (сохранение конфигураций) |
| F-A-09 | Биллинг API: получение планов, создание платёжной сессии (Telegram Stars / ЮKassa / Stripe) |
| F-A-10 | Детектирование языка (если source = auto) через внешний API или локально |
| F-A-11 | Endpoint статистики пользователя (для Mini App) |
| F-A-12 | Admin API: сброс квот, управление пользователями, просмотр статистики |

## 2. Нефункциональные требования

### 2.1 Производительность

| Параметр | Значение |
|---|---|
| Median latency перевода (end-to-end) | ≤ 2 сек |
| P95 latency | ≤ 5 сек |
| Пропускная способность | ≥ 100 RPS (bot + api суммарно) |
| Время старта контейнера | ≤ 10 сек |

### 2.2 Надёжность

- Uptime: 99.5% (SLA для MVP)
- Retry с экспоненциальным backoff для внешних MT-API
- Fallback: если основной провайдер недоступен → переключение на резервный
- Graceful degradation: если кэш недоступен → прямой запрос к MT-API

### 2.3 Безопасность и приватность

| Требование | Реализация |
|---|---|
| Авторизация Mini App | HMAC-валидация `initData` согласно Telegram docs |
| Хранение текстов | НЕ хранить оригинальные тексты (только хэш для кэша) |
| API-ключи MT-провайдеров | Только в environment variables, не в коде |
| HTTPS | Обязательно, Let's Encrypt |
| Логи | Без PII (только telegram_id, количество символов) |
| Telegram ID | Шифруется при хранении в БД (AES-256) |

### 2.4 Логирование и мониторинг

```
Логируем:
- Каждый запрос перевода: user_id (hashed), символов, провайдер, latency, статус
- Ошибки внешних API с трассировкой
- Превышения лимитов
- Платёжные события

НЕ логируем:
- Оригинальный текст сообщений
- Переведённый текст
- Username/имя пользователя

Инструменты:
- Structured logs (JSON) → stdout → собирает Loki/CloudWatch
- Метрики → Prometheus + Grafana (или Uptrace для MVP)
- Алерты: Telegram-бот → уведомления в admin-чат при error rate > 1%
```

### 2.5 Масштабируемость

- Бот и API — stateless, горизонтальное масштабирование
- Redis для сессий и кэша (не в памяти приложения)
- База данных — connection pooling (PgBouncer или встроенный)

## 3. Ограничения v1 (сознательные)

```
1. Только текстовые сообщения (не голос, не файлы, не стикеры)
2. Только Bot API (не MTProto) — доступ только к чатам где есть бот
3. Авто-перевод только публичных каналов (через getUpdates) — не приватных
4. Платёжная система — только Telegram Stars (простейшая интеграция), остальное v2
5. Максимум 5 авто-переводимых чатов на пользователя (free tier)
6. История переводов хранится 30 дней
7. Детект языка — через внешний API (не встроенный ML)
8. Нет Web версии (только Mini App внутри Telegram)
9. Нет команды для одновременного массового перевода истории чата
10. Нет поддержки форматирования (Markdown/HTML в переводе может не сохраняться)
```
